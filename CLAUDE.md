# CLAUDE.md — Figma → code integration rules (Lock In Bud)

Scope: repository root. This repo is **not** a formal monorepo with a shared workspace or shared token package; it is a multi-project layout (`web/`, `ios/`, `backend/`, `docs/`) that ships one product across a Next.js PWA, a SwiftUI iOS/Mac app, widgets, and a FastAPI service. When a Figma design targets more than one client, implement each client with its **native** primitives rather than forcing web CSS into SwiftUI or vice versa.

## 0. Golden rules

1. **Read before writing.** Load the mandatory Figma skill and call `create_session` before any Figma file read. Use `get_design_context` as the primary reference, not a final code dump.
2. **Adapt, do not paste.** Map Figma styles to the existing CSS variables / SwiftUI semantic styles and to existing components. Reuse before inventing.
3. **No Next.js from memory.** `web/AGENTS.md` warns that this is Next 16 with breaking changes. Read the matching guide in `web/node_modules/next/dist/docs/` before writing Next code. `web/CLAUDE.md` is just `@AGENTS.md`.
4. **Assets are committed, never hot-linked.** Download Figma exports into `web/public/` or `ios/MyApp/Assets.xcassets/`; never put a temporary Figma export URL in source, CSS, JSON, or manifests.
5. **Verify in this repo's own harness** (typecheck/build/Playwright; `xcodebuild test`; pytest when APIs change) and inspect the final `git diff`.

## 3. Design tokens — current sources of truth

### Web: CSS custom properties in `web/src/app/globals.css`

Format is one-line CSS declarations on `:root`; there is **no** token JSON, Style Dictionary, Tailwind config, CSS module, or other transformation system. Figma variables must be mapped by hand to these names.

```css
:root { color-scheme: light; --bg: #f2f2f7; --surface: #fff; --text: #000; --muted: #636366;
  --line: #d1d1d6; --accent: #0062cc; --on-accent: #fff; --accent-soft: #eaf3ff;
  --danger: #c93430; --success: #248a3d; --orange: #a65d00; --shadow: 0 12px 48px #00000020; }

@media (prefers-color-scheme: dark) {
  :root:not([data-theme="light"]) { color-scheme: dark; --bg: #000; --surface: #1c1c1e;
    --text: #fff; --muted: #aeaeb2; --line: #38383a; --accent: #64b5ff; --on-accent: #000;
    --accent-soft: #102b48; --danger: #ff6961; --success: #30d158; --orange: #ff9f0a;
    --shadow: 0 12px 48px #0006; }
}
:root[data-theme="dark"] { /* same dark values, forced by app setting */ }
```

- Dark mode is driven by `prefers-color-scheme` unless `data-theme="light"`/`"dark"` is set on `:root`. iOS theme state lives in `ios/MyApp/Services/AppAppearance.swift` (`enum AppTheme { system, light, dark }`, persisted under `app.theme` in `UserDefaults`).
- **Typography is not tokenized**: `body` uses `-apple-system, BlinkMacSystemFont, "Segoe UI", sans-serif`, `16px`, `line-height: 1.5`; `h1` 32px/700/-0.8px, `h2` 19px/650, `h3` 16px/600; `.small`/`.eyebrow` 14px; `.timer-display` uses `clamp(40px, 5vw, 62px)` and `tabular-nums`.
- **Spacing/radii are literals**: 4/6/8/12/16/20/24/32/40px gaps and padding; 12px radius for buttons, inputs, cards; 16px for `.sheet`; 24px for `.login-card`; 44px minimum button/input height; max widths 1184px (`main`, `.app-header`), 1120px (`.tab-nav`, `.focus-strip`), 600px (`.sheet`).
- Other color literals outside `globals.css`: `web/src/app/layout.tsx` `themeColor` (`#f2f2f7` light / `#000000` dark), `web/public/manifest.webmanifest` (`background_color: #f2f2f7`, `theme_color: #007aff`), and `web/public/icon.svg` (`#007aff`). Treat these as brand/app-shell metadata, not UI tokens.
- Known drift to avoid propagating: `var(--border)` is referenced by `.chat-action` (`web/src/app/globals.css:198`) but is **not defined** in `:root`; use `var(--line)`. The `#007aff` manifest/icon blue also differs from `--accent` (`#0062cc` light, `#64b5ff` dark) — do not silently replace UI accents with the icon blue.

### iOS: asset catalog and Swift colors

- `ios/MyApp/Assets.xcassets/AccentColor.colorset/Contents.json` contains a single universal entry with **no explicit color values** (system tint is used). `ios/MyAppWidget/Assets.xcassets/AccentColor.colorset/Contents.json` is `{"source":"xcode"}`.
- `ios/MyApp/Assets.xcassets/AppIcon.appiconset/Contents.json` declares a 1024×1024 universal PNG plus dark/tinted appearances and Mac icon sizes; there is only one icon PNG (`AppIcon.png`). There are no image sets for UI illustrations.
- Semantic colors are used directly: `Color(.secondarySystemBackground)`, `.primary`, `.secondary`, `.green`, `.red`, `.orange`, `.blue`, `.tint`, `.regularMaterial`.
- The Figma redesign adds a shared, UI-only palette and primitives in `ios/MyApp/Views/Design/DesignSystem.swift`: `DesignPalette` (canvas `#f3f3eb`, ink `#202923`, forest `#3e663c`, sage `#e1e9d5`, sand `#e8e4d6`), `.appBackdrop()`, `AppHeader`, `AppCard`, `AppPrimaryButtonStyle`, `AppSecondaryButtonStyle`, `AppIconButton`. The separate `AppTheme` in `ios/MyApp/Services/AppAppearance.swift` remains the persisted light/dark/system setting. Per-screen Panda SVG exports live in `ios/MyApp/Assets.xcassets/*.imageset` and are **screen-specific**; never substitute one frame's Panda for another's.
- The only named numeric palette is local to `ios/MyApp/Views/Focus/FocusStatsView.swift`:

```swift
enum FocusChartColors {
    static let chartBackground = Color(red: 0.086, green: 0.094, blue: 0.12)
    static let primaryText = Color.white.opacity(0.9)
    static let secondaryText = Color.white.opacity(0.55)
    static let skyBlue = Color(red: 0.32, green: 0.66, blue: 0.93)
    static let palette: [Color] = [ /* 20 named RGB colors */ ]
}
```

**Transformation system: none on either client.** When a Figma design uses variables, translate them manually: Figma color variable → nearest `var(--…)` in `globals.css`; Figma text style → existing global class/element style or SwiftUI semantic font; Figma spacing → existing literal scale. Do not introduce a new token layer as a side effect of one design.

## 5. Assets and icon systems

### Web assets

- `web/public/icon.svg` is the source artwork: a 512×512 rounded square (`rx="112"`) filled `#007aff` with a white ring/check mark.
- `web/scripts/icons.mjs` generates raster variants with sharp:

```js
import sharp from "sharp";
for (const size of [180, 192, 512]) {
  await sharp("public/icon.svg").resize(size, size).png().toFile(
    size === 180 ? "public/apple-icon.png" : `public/icon-${size}.png`,
  );
}
```

Run `npm run icons` from `web/` after changing `icon.svg`. Generated files are `apple-icon.png`, `icon-192.png`, `icon-512.png`; they are referenced by `web/src/app/layout.tsx` metadata, `web/public/manifest.webmanifest`, and `web/public/sw.js` (`PUBLIC` cache list). Update all three if you rename assets.
- `web/public/sw.js` caches only the anonymous public shell, `/offline.html`, icons, and hashed `/_next/static` JS/CSS. It explicitly avoids `/api/`, RSC/prefetch headers, and account data. No `next/image` is used anywhere in the app (the only reference is in `web/next-env.d.ts`).
- Formats: SVG for the master icon, PNG for installable icons, plain CSS for UI graphics. No CDN config beyond Vercel; do not reference remote images from Figma.

### Icons in UI

- **Web:** `lucide-react` named imports, PascalCase component names, used as JSX (`<CalendarDays />`, `<X />`, `<CircleCheck />`). Sizing is centralized in CSS, e.g. `button svg { width: 19px; height: 19px; flex-shrink: 0; }` and `.brand svg { color: var(--accent); width: 25px; }`. Do not hand-draw SVGs when a Lucide equivalent exists; do not mix icon libraries.
- **iOS:** SF Symbols via `Image(systemName: "calendar.badge.clock")` and `Label("Tasks", systemImage: "checklist")`. Apple's lowercase dot-separated names are the convention (`checkmark.circle.fill`, `pause.circle.fill`, `chart.bar.fill`, `star.fill`). Widgets and Live Activities follow the same convention (`ios/MyAppWidget/CurrentTaskWidgetView.swift`, `FocusLiveActivity.swift`, `FocusTimerWidget.swift`).
- When a Figma frame shows an icon, map it to the closest Lucide icon on web and the closest SF Symbol on iOS. Keep accessible labels; do not export an icon as a bitmap.

## 6. Styling approach

### Web

- Single global stylesheet: `web/src/app/globals.css`, imported once in `web/src/app/layout.tsx` (`import "./globals.css";`). No CSS modules, Tailwind, CSS-in-JS, or utility framework.
- Components reference semantic class names defined there (`.card`, `.stack`, `.row`, `.grow`, `.muted`, `.small`, `.eyebrow`, `.icon-button`, `.primary`, `.danger`, `.sheet`, `.tab-nav`, `.task-row`, `.timer-display`, …). Prefer composing these over adding scoped one-off CSS.
- Theme: `prefers-color-scheme` plus explicit `data-theme`; reduced motion via two `@media (prefers-reduced-motion: reduce)` blocks (lines 194 and 218); focus ring via `:focus-visible`; 44px minimum hit targets.
- Responsive breakpoints: `max-width: 1000px` (tighter schedule layout), `760px` (bottom fixed 4-column tab bar, single-column grids, bottom-sheet dialog with `env(safe-area-inset-bottom)`), `700px` (task/session/focus strip wrapping), `min-width: 1100px` (assistant side panel; `.planner:has(.assistant-panel[open]) { padding-right: 420px; }`). Use `dvh` and `env(safe-area-inset-*)` as the existing code does.
- Accessibility patterns to preserve: `role="status"`/`aria-live="polite"` sync banner, `aria-current` tabs, `aria-pressed` toggles, `aria-label` on dialogs and icon buttons, `.sr-only` for healthy state. Regression coverage is in `web/tests/ui-ux.spec.ts` (single-row mobile nav, no horizontal overflow, dark theme readability).

### SwiftUI

Use native layout and modifiers rather than translating web CSS:

```swift
// ios/MyApp/Views/OnboardingView.swift:54-61
Image(systemName: "calendar.badge.clock")
    .font(.system(size: 72))
    .foregroundStyle(.tint)
Text("...").font(.largeTitle)
Text("...").font(.subheadline).foregroundStyle(.secondary)
```

Common patterns: `.font(.caption/.footnote/.subheadline/.headline)`, `.foregroundStyle(.secondary)`, `.tint(.blue)`, `.padding()`, `.background(.regularMaterial, in: RoundedRectangle(cornerRadius: 12))`, `.safeAreaInset(edge: .top)`, `.monospacedDigit()`, `.accessibilityLabel(...)`. Keep dynamic type and system colors intact; do not hard-code hex colors except inside a dedicated palette like `FocusChartColors`.

## 7. Mandatory Figma MCP workflow

### 7.1 Parse the Figma URL before any tool call

- `https://www.figma.com/design/:fileKey/:fileName?node-id=123-456` → `fileKey = :fileKey`, `nodeId = "123:456"` (replace `-` with `:`).
- Branch URL `https://www.figma.com/design/:fileKey/branch/:branchKey/:fileName` → use `:branchKey` as the file key.
- `https://www.figma.com/make/:makeFileKey/:makeFileName` → use `:makeFileKey`.
- `.../board/:fileKey/:fileName?node-id=...` is FigJam (use `get_figjam`); `/slides/` and `/spec/` need their own flows. File tools only support `/design/` files.

### 7.2 Session and skill prerequisites

1. Once the target file key is known, call `create_session` with that key and a concise task description — **before** `search_design_system`, `get_libraries`, `get_metadata`, `get_design_context`, `get_screenshot`, or `use_figma`. This applies to read-only work too.
2. Reuse the returned `sessionId` on every subsequent file-tool call, including calls to a different `fileKey`.
3. If a new file is needed, call `create_new_file` first, then `create_session` with the returned key.
4. **Mandatory:** load the `/figma-design-to-code` skill (fallback `skill://figma/figma-design-to-code/SKILL.md`) **before calling `get_design_context`**.
5. Other flows have their own prerequisites: `/figma-use` before `use_figma`, `/figma-generate-design` for code→design pages, `/figma-generate-library` for design-system work, `/figma-code-connect` for component mapping, `/figma-generate-diagram` before `generate_diagram`.

### 7.3 Read and adapt

```text
create_session({ fileKey, description }) -> sessionId
get_design_context({ fileKey, nodeId, sessionId })   # primary reference
get_screenshot({ fileKey, nodeId, sessionId })       # optional visual cross-check
```

- Treat `get_design_context` output as a **reference to adapt to this repo**, not final code. Honor its hints by priority.
- First look for a design-system match (`search_design_system`) and an existing code component. Reuse `web/src/components/**`, `web/src/components/ui/**`, and `ios/MyApp/Views/**` before creating new components.
- Map colors to the CSS variables / SwiftUI semantic colors in §3; map spacing and typography to the existing scales in §6. Do not introduce Tailwind, a CSS-in-JS layer, a new icon library, or a token transformation package.
- Keep web and iOS idiomatic: global CSS + React/lucide on web; native modifiers + SF Symbols on iOS. `docs/client-parity.md` is the boundary; parity of behavior, not pixels.

### 7.4 Assets and URLs

- Download every raster/vector asset locally. Web: `web/public/` (and regenerate PWA icons with `npm run icons` if the app icon changes, updating `manifest.webmanifest` and `sw.js` if names change). iOS: the appropriate `Assets.xcassets` catalog.
- Give assets stable, descriptive file names and commit them. Never leave `https://figma.com/...` or signed export URLs in `.tsx`, `.css`, `.json`, `.swift`, or manifests — they expire and leak design-file access.
- Prefer an existing Lucide icon / SF Symbol over exporting an icon from Figma.

### 7.5 Code Connect (only for real component mappings)

- Load `/figma-code-connect` first. Check `get_code_connect_map` before adding a mapping.
- Use `add_code_connect_map` with the exact `fileKey`, `nodeId`, `source`, `componentName`, and `label` (`"React"` for `web/src/components/**`, `"SwiftUI"` for `ios/MyApp/Views/**`). Map actual reusable components, not arbitrary frames or one-off screens.

- Confirm no Figma URLs remain, all new assets are local, no temporary files were added, and `git diff --name-only` contains only intended files.
- For any Next.js API or file convention used, confirm it against `web/node_modules/next/dist/docs/` (resolved from `web/`), not training data. Do not delete the auto-generated `web/AGENTS.md` warning block.
